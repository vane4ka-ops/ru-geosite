# ru-geosite

Независимый генератор `custom.dat` для Xray GeoSite и Streisand. Проект
использует только списки из этого репозитория: автоматического получения
правил, синхронизации с upstream, VPS, внешних rule provider и постоянных
токенов нет.

Исходная основа: [artembolotov/custom-geosite](https://github.com/artembolotov/custom-geosite).
Уведомление об авторстве и лицензия MIT сохранены в [LICENSE](LICENSE).
`vane4ka-ops/ru-geosite` — самостоятельный репозиторий, не участник сети форков.
Ссылка на исходный проект служит только указанием авторства.

## Опубликованный файл

После успешного workflow в `main` файл доступен по адресу:

`https://vane4ka-ops.github.io/ru-geosite/custom.dat`

Рядом публикуется `custom.dat.sha256`. В настройках Pages выбран источник
**GitHub Actions**, HTTPS включён. Workflow разрешает публикацию только из
`main` репозитория `vane4ka-ops/ru-geosite`.

## Списки и правила

- `lists/direct.txt` — российские сервисы, которые должны идти без VPN;
- `lists/proxy.txt` — приоритетные сервисы, которые обязательно идут через VPN.

Поддерживаются `domain:example.ru` и `full:host.example.ru`; запись без
префикса равна `domain:`. Регистр не важен, дубликаты удаляются, а результат
сортируется. `regex:` намеренно запрещён: его сложнее безопасно ревьюить.

Перед добавлением убедитесь, что домен принадлежит нужному сервису и не
является чужим CDN или иностранной службой. История спорных записей — в
[`lists/REVIEW.md`](lists/REVIEW.md).

## Локальная сборка и проверка

Нужен Go `1.22.12`.

```bash
go test ./...
go run . -out custom.dat
go run . -check custom.dat
sha256sum custom.dat
```

Для проверки скачанных `custom.dat` и `custom.dat.sha256` положите оба файла
в одну папку и выполните в ней `sha256sum --check custom.dat.sha256`.

Одинаковые списки и версия Go дают одинаковый бинарный файл. Workflow повторяет
эти шаги, проверяет, что `direct` и `proxy` присутствуют, и публикует только
успешно собранный артефакт из `main`. Публикация также ждёт успешного завершения
CodeQL; его сбой или отмена блокируют deploy. Само успешное выполнение CodeQL
не означает отсутствия найденных уязвимостей: результаты смотрите в Security →
Code scanning. Pull request ничего не публикует.

## Изменение и выпуск

1. Создайте ветку и измените один из файлов в `lists/`.
2. Откройте pull request **в `vane4ka-ops/ru-geosite`**, дождитесь успешных
   `Validate and test` и `CodeQL / Analyze Go`. Базовая ветка — `main`.
3. Владелец `vane4ka-ops` проверяет изменения и выполняет merge. После merge
   в `main` Actions создаст и опубликует новую версию.

Для отката откройте историю `main`, создайте revert нужного коммита через
GitHub и смержите его после проверки. Предыдущая опубликованная версия остаётся
доступна, пока новая сборка не прошла все проверки и не была развёрнута.

## Streisand: пять шагов

1. Скачайте `custom.dat` по опубликованному URL и проверьте его SHA-256 по
   файлу `custom.dat.sha256`.
2. Импортируйте файл GeoSite в Streisand способом, который поддерживает ваша
   версия приложения.
3. Добавьте правило `ext:custom.dat:proxy` с маршрутом VPN выше остальных
   пользовательских правил.
4. Добавьте правило `ext:custom.dat:direct` с маршрутом DIRECT ниже правила
   `proxy`.
5. Оставьте правило по умолчанию с маршрутом VPN.

GitHub Pages обновляет файл на сервере, но не файл внутри Streisand. После
каждого релиза его нужно обновить/импортировать в приложении. Автоматическое
обновление зависит от версии Streisand; перед включением его следует сверить с
документацией используемой версии.

## Ограничения GitHub

Для `main` включены обязательный PR, актуальность ветки перед merge, успешные
проверки `Validate and test` и `CodeQL / Analyze Go`, разрешение обсуждений и
запрет force-push/удаления. Защита распространяется на администратора.

Единственный collaborator с правом записи — `vane4ka-ops`. `CODEOWNERS`
указывает его для всех файлов. Обязательное число сторонних approvals равно
нулю: GitHub не позволяет автору одобрить собственный PR, а второго владельца
нет. Решение о принятии изменений принимает владелец через merge; auto-merge
выключен.

Окружение `github-pages` допускает деплой только из ветки `main`. Токен Actions
по умолчанию доступен только для чтения; права на Pages/OIDC выдаются отдельной
задаче публикации. Включены Dependabot security alerts. Dependabot может
предлагать обновления зависимостей через PR, но не меняет списки доменов и не
сливает изменения автоматически.
